# 01 · 总体设计（目标平台：Android / 免 root）

> 项目代号建议：**AdShield**（工作名，可改）
> 本文档只做设计与规格，不包含可运行代码；代码在方案确认后按里程碑产出。

---

## 1. 结论摘要

1. 在 **Android 免 root** 条件下，可以同时做到三件事：**广告域名请求拦截**（本地 VPN + DNS）、**开屏/弹窗自动跳过**（无障碍服务）、**拦截与跳过次数统计**（本地数据库 + 报表）。
2. 两套能力**互为补充、不可互相替代**：
   - VPN/DNS 层能打掉绝大多数第三方广告 SDK 的素材与接口请求，但**拦不住**"自家域名 + 自有广告位"（例如某些电商、短视频 App 用第一方域名下发广告）。
   - 无障碍层能点掉**已经显示出来的**开屏广告与弹窗，但**不能阻止**广告请求（流量与耗电已经发生）。
3. 因此产品形态固定为 **"双引擎 + 统一统计"**，两个引擎各自可独立开关。
4. "删除其它 App 里的广告"这件事**不做**：需要反编译/重打包第三方应用，属于侵权且带来签名、安全、法律风险。等效效果通过上面两种运行时手段达成。
5. 关键工程约束（决定了整个设计）：
   - **VPN 同一时刻只能有一个**：用户开了代理/公司 VPN，本 App 就无法工作，必须做冲突检测与引导。
   - **DNS 归因到具体 App 不是 100% 可靠**：需要 `getConnectionOwnerUid`（Android 10+），失败时降级为"全局计数 + 未归因"，不能向用户承诺精确到 App 的绝对准确。
   - **Android 9+ 的"私人 DNS"（DoT）会绕过本地 DNS 拦截**，必须检测并引导关闭或设为"自动"。
   - **浏览器/内置 DoH 的 App 无法拦截**，需在能力边界里明确写清。
   - **无障碍权限是高风险权限**：误点付费按钮、误关正常弹窗都可能发生，必须内置安全阀。

## 2. 产品范围

### 2.1 做什么（In Scope）

| 能力 | 说明 |
|---|---|
| 域名级广告拦截 | 基于订阅规则 + 用户自定义黑/白名单，对所有 App 的网络请求生效 |
| 开屏广告自动跳过 | 识别"跳过/关闭/跳过广告"等控件，自动点击（可设置延迟） |
| 弹窗广告自动关闭 | 识别插屏、横幅关闭按钮，按规则点击 |
| 弹窗记录 | 记录"出现时间 + App + 规则 + 是否成功跳过 + 耗时" |
| 请求记录 | 记录"被拦截的域名 + 次数 + （可归因时）App" |
| 统计报表 | 今日/7 天/累计；按 App 排行；时间线；拦截节省估算 |
| 规则管理 | 内置基础规则、在线订阅更新、单条开关、自定义规则 |
| 白名单 | 指定 App 完全不做无障碍处理（防误触），指定域名不做拦截（防功能不可用） |
| 导出 | CSV / JSON 导出记录，便于自行分析 |

### 2.2 不做什么（Out of Scope，明确排除）

| 不做的事 | 原因 |
|---|---|
| 反编译 / 重打包 / 修改其它 App 的 APK | 侵权、破坏签名校验、法律风险高 |
| 破解会员、绕过付费去广告 | 违反《著作权法》与服务条款，不属于"屏蔽广告" |
| 拦截 HTTPS 正文内容（MITM 中间人解密） | 需要用户安装根证书，安全风险极大，仅可作为本地调试实验，不进入正式功能 |
| 上传用户浏览/请求数据到服务器 | 隐私红线；全部数据留在本机 |
| 提供规则订阅的付费内容或盗版资源 | 合规边界 |

## 3. 平台与版本可行性

| 能力 | 最低版本 | 说明 |
|---|---|---|
| `VpnService` 本地 DNS 拦截 | API 21（5.0） | `addDisallowedApplication` 也是 21+ |
| `getConnectionOwnerUid` 流量归因 | API 29（10） | 29 以下只能做全局计数 |
| `AccessibilityService` + 视图树 | API 21+ | `flagRetrieveInteractiveWindows` 从 API 21 起可用，需在 XML 显式声明 |
| `dispatchGesture` 手势点击 | API 24（7.0） | 作为 `ACTION_CLICK` 失败时的兜底 |
| 前台服务类型 `specialUse` | API 34（14） | 14+ 必须声明类型并写 `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` |
| 通知权限 `POST_NOTIFICATIONS` | API 33（13） | 未授权则常驻通知不显示，需引导 |
| 包可见性（列出已安装 App） | API 30（11） | 需 `<queries>` 或 `QUERY_ALL_PACKAGES`（Play 需申报），旁加载可直接用 |

目标区间：**minSdk 26（8.0）**，`targetSdk 35`。理由：8.0 以下设备占比极低，26 起可以省掉大量兼容分支（通知渠道、后台限制等）。

## 4. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│                        :app （UI 层，Compose）                │
│  首页仪表盘 │ 拦截记录 │ 跳过记录 │ 规则管理 │ 设置 │ 引导授权  │
└───────────────┬──────────────────────────────┬───────────────┘
                │ ViewModel / UseCase          │
┌───────────────▼──────────────────────────────▼───────────────┐
│                     :core-domain（用例与模型）                │
│  ToggleVpnUseCase │ ToggleA11yUseCase │ QueryStatsUseCase    │
│  RuleRepository（接口） │ StatsRepository（接口）              │
└──────┬───────────────┬───────────────┬───────────────┬───────┘
       │               │               │               │
┌──────▼──────┐ ┌──────▼──────┐ ┌──────▼──────┐ ┌──────▼──────┐
│ :core-vpn   │ │ :core-a11y  │ │ :core-rules │ │ :core-data  │
│ VpnService  │ │ A11yService │ │ 规则解析/    │ │ Room/       │
│ DNS 代理    │ │ 规则引擎     │ │ 订阅更新     │ │ DataStore   │
│ 归因(uid)   │ │ 安全阀       │ │ hosts 导入   │ │             │
└──────┬──────┘ └──────┬──────┘ └──────┬──────┘ └──────┬──────┘
       │               │               │               │
       └───────────────┴───────┬───────┴───────────────┘
                               │
                     ┌─────────▼──────────┐
                     │ 进程内事件总线      │
                     │ (SharedFlow / AIDL)│
                     └────────────────────┘
```

两个引擎与 UI 处于**同一进程**（`android:process` 不拆分），统一由 `AppContainer` 提供单例依赖，避免跨进程同步成本。VpnService 与 AccessibilityService 都是系统绑定的组件，靠 `startService`/系统回调拉起，进程被回收后由系统重启（`START_STICKY` + 引导用户关闭电池优化）。

### 4.1 一次"开屏广告"的完整数据流

```
用户点击图标启动 App X
   │
   ├─(网络侧) App X 请求 ads.xxx.com/v1/splash
   │     └─ 报文进入 TUN → DnsProxy 判定命中规则
   │          ├─ 命中 → 返回 0.0.0.0，写入 blocked_domain 事件（+ uid 归因）
   │          └─ 未命中 → 转发上游 DNS（protect 后的 socket）
   │
   └─(界面侧) 广告 Activity 弹出，无障碍事件 windowStateChanged(pkg=X)
         └─ A11yEngine 取视图树 → 规则匹配"跳过 5"节点
              ├─ 高置信 → 延迟后点击，写入 popup_event(skipped=true)
              └─ 低置信/命中黑名单 → 只记录不点击，写入 popup_event(skipped=false)
                      │
                      ▼
              StatsAggregator（内存聚合 + 落库）
                      │
                      ▼
              首页仪表盘："今日拦截 128 次 · 自动跳过 14 次 · 约省 3 分 20 秒"
```

## 5. 模块与关键类职责

### 5.1 模块划分

| Gradle 模块 | 类型 | 职责 |
|---|---|---|
| `:app` | Android App | 导航、Compose 界面、权限引导、前台服务声明 |
| `:core-domain` | Kotlin lib | 纯业务：用例、实体定义、仓储接口 |
| `:core-data` | Android lib | Room 数据库、DataStore 偏好、仓储实现 |
| `:core-rules` | Kotlin lib | 规则模型、解析（JSON/hosts）、匹配算法（纯函数，易写单测） |
| `:core-vpn` | Android lib | `VpnService`、TUN 读写、DNS 报文编解码、上游转发、uid 归因 |
| `:core-a11y` | Android lib | `AccessibilityService`、视图树遍历、点击执行、安全阀 |
| `:core-ui` | Android lib | 设计系统（配色、组件、图表） |

### 5.2 关键类清单（开发时的"骨架清单"）

| 类 | 模块 | 职责要点 |
|---|---|---|
| `AdShieldVpnService : VpnService` | core-vpn | 建立 TUN、启动/停止 `DnsProxy`、监听系统 VPN 冲突 |
| `TunBuilderFactory` | core-vpn | 组装 `Builder`（地址、路由、DNS、排除自身包、MTU） |
| `DnsProxy` | core-vpn | TUN 读写循环；UDP/TCP 53 解析；命中判定；转发；写事件 |
| `DnsMessageCodec` | core-vpn | DNS 报文解析/构造（A/AAAA/HTTPS 记录，返回 0.0.0.0 / NXDOMAIN） |
| `DomainMatcher` | core-rules | 域名后缀树/哈希匹配，支持通配与白名单优先级 |
| `UidResolver` | core-vpn | `ConnectivityManager.getConnectionOwnerUid` 封装 + 缓存 + 降级 |
| `RuleSourceLoader` | core-rules | hosts / EasyList / 自研 JSON 规则加载与归一化 |
| `AdShieldA11yService : AccessibilityService` | core-a11y | 事件过滤、窗口快照、超时保护、生命周期 |
| `NodeTreeWalker` | core-a11y | 有界 BFS 遍历节点，产出候选节点（限制节点数与耗时） |
| `PopupRuleMatcher` | core-rules | 文本正则 / viewId / contentDescription / 控件类型组合匹配 |
| `ClickExecutor` | core-a11y | `ACTION_CLICK` 优先，失败回退 `dispatchGesture`；点击后校验窗口是否消失 |
| `SafetyGuard` | core-a11y | 频率限制、危险关键词拦截（支付/开通/下载）、白名单校验 |
| `PopupEventRecorder` | core-data | 事件去重（同一窗口只记一次）、写入 Room |
| `StatsAggregator` | core-data | 日聚合、7 日、按 App 排行、节省时间估算 |
| `RuleUpdateWorker` | core-rules | WorkManager 定时拉取规则订阅、校验、原子替换 |
| `PermissionStateChecker` | :app | 汇总 VPN/无障碍/通知/电池优化状态，驱动引导页 |

## 6. 技术选型

| 维度 | 选择 | 理由 |
|---|---|---|
| 语言 | Kotlin 2.x | 协程 + 密封类适合状态机式引擎 |
| UI | Jetpack Compose + Material 3 | 列表/图表迭代快 |
| 架构 | MVVM + 单向数据流（StateFlow） | 便于测试 |
| 依赖注入 | Hilt | 多模块下 Service 注入最省事 |
| 本地库 | Room（事件、规则命中）+ DataStore Proto（开关、白名单） | 高频写入用 Room，配置用 DataStore |
| 后台任务 | WorkManager（规则更新）+ 前台服务（VPN） | 规则更新不需要精确时间 |
| 网络 | OkHttp（仅用于规则订阅下载） | 与广告拦截无关，避免混淆 |
| DNS 编解码 | 自研轻量实现（不做完整 RFC 栈） | 只需 A/AAAA/HTTPS/CNAME 与 NXDOMAIN，引第三方库反而臃肿 |
| 日志 | Timber（debug）+ 环形内存日志（用户可导出，脱敏） | |
| 测试 | JUnit5（core-rules 纯逻辑）+ Robolectric（Service 装配）+ 真机脚本 | 规则匹配必须单元测试覆盖 |
| 构建 | AGP 8.x，Kotlin DSL，Version Catalog | |

## 8. 借鉴边界（重要）

- 可参考的**公开思路**：DNS66 / Blokada 的"仅路由 DNS 服务器"做法、AdAway 的 hosts 来源、GKD 的"规则订阅 + 选择器"产品形态。
- **不可直接复制代码**：GKD 为 GPL-3.0，直接引用会传染本项目许可；hosts/EasyList 各自有许可（CC BY-SA、GPL、MIT 等），分发时必须保留署名与许可声明，且**不要打包进 APK 再闭源分发**，建议运行时下载 + 显示来源与许可。
- 规则格式**自研**（见 `03-无障碍自动跳过设计.md`），只借鉴"声明式选择器 + 订阅"的概念，不照搬实现。
