# 03 · 界面侧设计：无障碍服务自动跳过广告

## 1. 能力边界

**能做**：识别并点击已经渲染出来的"跳过 / 关闭"控件；识别全屏广告 Activity 并记录；按 App 定向规则处理插屏、横幅关闭按钮。
**不能做**：阻止广告请求（流量已发生）；处理 WebView 画布内绘制的广告（无节点树，几乎无法定位）；处理游戏引擎（Unity/UE）自绘界面（部分机型有节点，多数没有）；点击系统级权限弹窗。

---

## 2. Service 声明与系统约束

```xml
<service
    android:name=".a11y.AdShieldA11yService"
    android:exported="true"
    android:label="@string/a11y_label"
    android:permission="android.permission.BIND_ACCESSIBILITY_SERVICE">
    <intent-filter>
        <action android:name="android.accessibilityservice.AccessibilityService"/>
    </intent-filter>
    <meta-data android:name="android.accessibilityservice"
               android:resource="@xml/a11y_config"/>
</service>
```

`res/xml/a11y_config.xml`：

```xml
<accessibility-service xmlns:android="http://schemas.android.com/apk/res/android"
    android:accessibilityEventTypes="typeWindowStateChanged|typeWindowContentChanged"
    android:accessibilityFeedbackType="feedbackGeneric"
    android:accessibilityFlags="flagDefault|flagIncludeNotImportantViews|flagReportViewIds|flagRetrieveInteractiveWindows"
    android:canRetrieveWindowContent="true"
    android:canPerformGestures="true"
    android:notificationTimeout="80"
    android:description="@string/a11y_description"
    android:isAccessibilityTool="false" />
```

要点：

| 项 | 说明 |
|---|---|
| `isAccessibilityTool="false"` | **必填**。本功能不属于辅助残障，声明为 true 属虚假声明；同时这意味着在 Google Play 上会进入严格审核（见 `05-权限与合规.md`） |
| `notificationTimeout="80"` | 事件合并窗口，避免 `CONTENT_CHANGED` 洪水；不要设 0 |
| `flagIncludeNotImportantViews` | 广告跳过按钮常被标为 unimportant，不加则取不到 |
| 系统限制 | Android 11+ 禁止无障碍服务点击**系统授权/安装弹窗**；本 App 也不需要，但要在规则里显式排除 `com.android.packageinstaller`、`com.google.android.permissioncontroller` |

激活状态检查：`Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES` + `AccessibilityManager.getEnabledAccessibilityServiceList`，两者都查（部分 ROM 只更新其一）。

## 3. 处理链路（状态机）

```
onAccessibilityEvent(event)
  │
  ├─ 0. 丢弃条件：服务被用户关闭 / 目标包在白名单 / 包名属于系统UI / 屏幕关闭
  ├─ 1. 会话判定：目标包是否刚进入前台？（FrontSession{pkg, activityName, sinceTs}）
  │       · 由 TYPE_WINDOW_STATE_CHANGED 建立，仅在 [0, 8000ms] 内允许动作
  │       · 超出窗口 → 仅记录，不点击（防误触）
  ├─ 2. 去抖：同一 pkg 在 250ms 内只处理一次（合并连续 CONTENT_CHANGED）
  ├─ 3. 快照：rootInActiveWindow → NodeTreeWalker 有界 BFS（≤400 节点 / ≤30ms）
  ├─ 4. 匹配：app 定向规则 → 全局规则；产出候选 (node, rule, confidence)
  ├─ 5. 安全阀：SafetyGuard.check() → 通过/拒绝（§6）
  ├─ 6. 执行：ClickExecutor（ACTION_CLICK → 祖先 → dispatchGesture）
  ├─ 7. 校验：延迟 600~1000ms 后判断窗口/节点是否消失 → success
  └─ 8. 记录：PopupEventRecorder（去重键 = pkg + activity + ruleId + 10s 桶）
```

### 3.1 为什么必须限定"进入前台后的时间窗口"

用户在日常使用中也会遇到"关闭""取消"等按钮，如果没有时间窗口限制，误触概率极高（尤其是"关闭订单""取消订阅"）。**默认策略：只处理 App 冷启动/切回前台后 8 秒内的界面**（开屏广告的典型生命周期），并在规则中允许单 App 延长到 15 秒。

## 4. 规则模型（自研格式）

`assets/builtin_rules.json`（内置只放通用安全规则）+ 远端订阅同格式。

```json
{
  "schema": 1,
  "version": 2026111101,
  "rules": [
    {
      "id": "generic.splash.skip",
      "name": "通用开屏跳过",
      "scope": { "type": "global" },
      "phase": "splash",
      "match": {
        "anyOf": [
          { "text": { "regex": "^(跳过|跳过广告|跳过\\s*\\d{1,2}s?|关闭广告)$" } },
          { "desc": { "regex": "跳过(广告)?" } }
        ]
      },
      "filter": {
        "clickableOrClickableAncestor": true,
        "visible": true,
        "minWidthDp": 20, "minHeightDp": 20,
        "maxTextLen": 16,
        "excludeTextRegex": "支付|付款|开通|购买|续费|同意|允许|下载|安装",
        "zones": ["topRight", "bottomRight", "anyCorner"]
      },
      "action": { "type": "click", "delayMs": 250, "retry": 1, "cooldownMs": 30000 },
      "confidence": 80
    },
    {
      "id": "app.demo.video.splash",
      "name": "示例视频 App 开屏",
      "scope": { "type": "app", "package": "com.example.video", "activityRegex": ".*(Splash|Ad)Activity.*" },
      "phase": "splash",
      "match": { "anyOf": [ { "viewId": { "regex": ".*:id/(skip|ad_skip|countdown_skip)" } } ] },
      "filter": { "clickableOrClickableAncestor": true, "visible": true },
      "action": { "type": "click", "delayMs": 0, "retry": 2, "cooldownMs": 0 },
      "confidence": 95
    }
  ]
}
```

### 4.1 字段语义

| 字段 | 说明 |
|---|---|
| `scope` | `global` 或 `app`（含 `package` 与可选 `activityRegex`）。**app 定向规则优先级高于 global** |
| `phase` | `splash`（前台 0–8s）/ `any`（前台会话内任意时刻，慎用） |
| `match.anyOf` | 命中任一即算匹配；`text` / `desc` / `viewId` 三种选择器，均为 RE2 子集正则（禁用回溯炸弹） |
| `filter` | 硬性约束：可点击、可见、尺寸下限、文本长度上限、危险词排除、位置象限 |
| `action` | `click` / `swipeUp`（部分插屏需上滑关闭）/ `back`（极少用，风险高，默认禁用） |
| `confidence` | 0–100，用于多规则命中时择优与 UI 展示 |
| `cooldownMs` | 同规则冷却，防止连点 |

### 4.2 规则校验（加载时）

- 正则编译失败、字段越界、`action=back` 出现在 global 规则 → 整条丢弃并记日志。
- 单次订阅最多 5000 条，单条正则长度 < 256，编译后总耗时 < 50ms（超时则丢弃剩余并提示）。
- 规则集必须带 `version`，按版本号原子替换（先写临时表，再切换指针），失败保留旧版。

## 5. 遍历与匹配的性能设计

| 约束 | 值 |
|---|---|
| 单次遍历节点上限 | 400 |
| 单次遍历耗时上限 | 30ms（超时立即返回已收集候选） |
| BFS 深度 | ≤ 12 层 |
| 跳过的子树 | 不可见 + 无文本 + 无 desc + 无 viewId 的容器子树（用 `isVisibleToUser` 剪枝） |
| 节点复用 | API < 33 时遍历结束统一 `recycle()`；33+ 已废弃，仍写 `if (Build.VERSION.SDK_INT < 33)` 分支保证老机型不泄漏 |
| 字符串获取 | 只在节点有 `text` 或 `contentDescription` 时取，且先判 `null`，避免无谓 IPC |

匹配顺序：先按 `viewId` 精确/正则（最快、最准），再按 `text`，最后 `desc`。**同一节点只允许被一条规则采纳**（按 confidence 降序取第一条通过安全阀的）。

## 6. 安全阀（`SafetyGuard`）——这是本项目最容易被忽视的部分

| 阀 | 规则 | 目的 |
|---|---|---|
| 包白名单 | 用户标记的 App 完全不处理 | 防误触（如银行、支付、政务类） |
| 系统包黑名单 | `com.android.*`、`com.google.android.permissioncontroller`、输入法、桌面 | 防系统级误操作 |
| 频控 | 同 App 10s 内 ≤ 3 次点击；同节点指纹 30s 内 ≤ 1 次 | 防连点/死循环 |
| 危险词硬拦截 | 命中 `支付|付款|开通|购买|续费|领取|同意|允许|下载|安装|授权` 的节点**永不点击**（即使规则写了） | 防财产损失与合规事故 |
| 窗口期 | 默认仅前台 0–8s | 防日常误触 |
| 全局熔断 | 单 App 连续 5 次点击后窗口未变化 → 该 App 本次会话停用 | 防规则失效导致疯狂点击 |
| 完全关闭开关 | 一键停用全部无障碍动作（保留记录） | 应急 |
| 首次启用演示 | 首次开启时在"演示 App"里跑一遍命中流程，让用户看清会发生什么 | 知情同意 |

> **绝不自动点击"同意/允许"类控件**是硬性产品红线：隐私与权限弹窗必须由用户本人决定。

## 7. 点击执行（`ClickExecutor`）

```
1) 目标节点 isClickable → performAction(ACTION_CLICK)
2) 否则向上找 ≤3 层可点击祖先 → ACTION_CLICK
3) 仍失败 → 取 boundsInScreen 中心点（向内收缩 20%），dispatchGesture(单点，duration 60ms)
4) 校验：600ms 后重新取 rootInActiveWindow，若目标节点消失或 Activity 变化 → success=true
5) 失败且 retry>0 → 按 cooldown 重试，最多 2 次
```

注意：
- `dispatchGesture` 需要 `canPerformGestures="true"`，且**在部分 ROM 上会被拦截**（返回 false），必须检查返回值并记录 `gestureRejected` 指标。
- 不要用 `GLOBAL_ACTION_BACK` 关广告：会把用户弹出 App，体验极差，且容易误操作。仅在明确标注的规则里允许。
- 点击坐标要用**屏幕坐标**，并处理分屏/折叠屏（`boundsInScreen` 与窗口偏移不一致的情况，取节点 bounds 而非硬编码）。

## 8. 与网络引擎的协同

两个引擎共用 `EventBus`（进程内 `SharedFlow<AdEvent>`），事件类型：

```kotlin
sealed interface AdEvent {
    data class DomainBlocked(val domain: String, val uid: Int?, val pkg: String?, val ts: Long) : AdEvent
    data class PopupDetected(val pkg: String, val activity: String, val ruleId: String?,
                             val nodeText: String?, val ts: Long) : AdEvent
    data class PopupSkipped(val pkg: String, val activity: String, val ruleId: String,
                            val latencyMs: Int, val method: ClickMethod) : AdEvent
}
```

- 归因融合：若 5 秒内同一 pkg 既有 `DomainBlocked` 又有 `PopupDetected`，在记录页合并显示为"一次广告事件（已拦截请求 + 已跳过界面）"。这条规则让统计页读起来接近用户直觉。
- 去重：`DomainBlocked` 按 (pkg, domain, 1 分钟桶) 聚合计数；`PopupDetected` 按 (pkg, activity, ruleId, 10 秒桶) 只记一次。

## 9. 规则来源与维护

| 来源 | 用途 | 分发方式 |
|---|---|---|
| 内置通用规则 | 开屏/插屏的通用"跳过"识别 | 随 APK 打包（自有内容，无许可问题） |
| 自建订阅 | 自己维护的 App 定向规则 | 自建静态 JSON（GitHub Pages / 对象存储），版本号更新 |
| 社区订阅（可选） | 参考 GKD 等社区规则思路 | **不做默认内置**；若集成需遵守其许可（GPL-3.0）并显著署名，或仅提供"用户手动添加订阅地址" |

规则迭代节奏：每 2 周一次；每条规则带 `id` 与 `version`，命中率（点击后窗口消失比例）作为质量指标，低于 30% 自动下架并提示用户反馈。

## 10. 真机验证要点（界面侧）

1. 开启服务后打开一个含开屏广告的 App：应在广告出现后 1s 内被跳过，且记录页出现一条"已跳过"。
2. 打开银行/政务类 App（加入白名单后）：不应发生任何点击。
3. 触发一个含"同意/允许"的隐私弹窗：**必须不点**，且记录中标记为 `blocked_by_safety`。
4. 快速连续启动同一 App 10 次：不应出现连点、不应卡顿（记录 App 前台帧率）。
5. 无障碍关闭 → 记录页显示"界面侧已停用"状态，不产生新记录。
6. 与 VPN 同时开启：两个引擎互不影响（同时验证一次"请求被拦 + 界面被跳过"的合并记录）。
7. 长时压测：刷短视频 30 分钟，观察 CPU（`top`）本 App 占比应 < 2%。
