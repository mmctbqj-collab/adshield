# 06 · 里程碑、风险与真机验证

## 1. 里程碑（单人估算，仅供参考）

| 里程碑 | 内容 | 产出 | 预估 |
|---|---|---|---|
| **M0 骨架** | 多模块工程、版本目录、`AppContainer`、空 Service、首页框架 | 可编译可安装的空壳 | 1–2 天 |
| **M1 请求拦截可用** | `VpnService` + 仅 DNS 路由 + DNS 代理 + 域名匹配 + 内存计数落库 + 首页大数字 | 真机可拦截，统计可见 | 4–6 天 |
| **M1.1 归因与健壮性** | `getConnectionOwnerUid` 归因、动态路由、TCP 53、私人 DNS 检测、诊断页 | 可按 App 展示 + 切网不失效 | 2–3 天 |
| **M2 界面跳过可用** | 无障碍服务 + 有界遍历 + 规则匹配 + 安全阀 + 点击校验 + 弹窗记录 | 开屏广告可自动跳过并记录 | 5–7 天 |
| **M3 规则与报表** | 规则订阅更新、规则页、记录页筛选、趋势图、App 详情、导出 | 完整产品形态 | 4–5 天 |
| **M4 加固** | 隐私级别、崩溃与异常兜底、耗电优化、多 ROM 适配、帮助页、签名与发布 | 可长期日用 | 3–5 天 |

关键依赖顺序：M0 → M1 →（M1.1 与 M2 可并行）→ M3 → M4。

### 1.1 每个里程碑的验收标准（DoD）

**M1**
- [ ] 开启后 `ad.qq.com`、`googleads.g.doubleclick.net` 解析失败；`www.baidu.com` 正常。
- [ ] 关闭 Wi-Fi / 切蜂窝后拦截仍生效（至少 1 次切网不失效）。
- [ ] 与其它 VPN 同时开启有明确提示，不崩溃。
- [ ] 连续运行 8 小时，待机耗电增量 ≤ 3%。
- [ ] 记录 1 分钟内可写入并显示在首页。

**M1.1**
- [ ] 至少 2 台设备（1 台 Android 10+，1 台 12+）验证归因成功率，UI 如实显示"未知来源"占比。
- [ ] 系统"私人 DNS"开启时，App 能检测并提示（不静默失败）。

**M2**
- [ ] 3 个不同 App 的开屏广告被成功跳过（延迟 < 1.5s）。
- [ ] 白名单 App 零点击；含"同意/支付"的弹窗零点击。
- [ ] 同一 App 连续 10 次启动无连点、无 ANR、无疯狂点击。
- [ ] 无障碍关闭后不再产生新记录，状态如实反映。

**M3**
- [ ] 规则订阅可更新、可回滚（断网时保留旧规则）。
- [ ] 记录页 1 万条数据滚动不卡（P95 帧时间 < 16ms 的滚动）。
- [ ] 导出 CSV 可在 Excel 正常打开（中文不乱码）。

**M4**
- [ ] 三档隐私级别生效（域名打码/不记录域名）。
- [ ] 强杀进程后恢复：VPN 与记录状态正确。
- [ ] 5 款不同厂商 ROM 完成冒烟测试（见 §3）。

## 2. 风险登记表

| # | 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| R1 | 部分 ROM 的 `getConnectionOwnerUid` 返回 -1，无法按 App 归因 | 高 | 中 | 如实显示"未知来源"；设置页提供归因自检；不承诺精确 |
| R2 | 系统私人 DNS（DoT）或 App 内置 DoH 绕过拦截 | 高 | 高 | 检测并引导关闭；把常见 DoH 域名加入黑名单 |
| R3 | 国产 ROM 杀后台，VPN 被断 | 高 | 高 | 引导电池白名单、自启动；前台通知常驻；`START_STICKY` |
| R4 | 与代理/加速器类 App 的 VPN 冲突 | 中 | 中 | 启动前检测并给出切换指引；支持"仅无障碍模式" |
| R5 | 无障碍规则覆盖率低，用户觉得"没用" | 高 | 高 | 内置通用规则 + 可自建规则 + 一键反馈 + 命中率统计下架机制 |
| R6 | 误点造成实际损失（付款、同意隐私协议） | 中 | **极高** | 危险词硬拦截、窗口期限制、白名单、熔断、首次演示 |
| R7 | 规则/域名列表许可不合规 | 中 | 高 | 不内置第三方规则；运行时订阅 + 保留许可信息 |
| R8 | 应用商店以无障碍/VPN 政策拒绝上架 | 高（若上架） | 中 | 侧载/开源分发；上架版拆分能力 |
| R9 | DNS 缓存导致"开了没效果" | 高 | 低 | 帮助页说明；提供"刷新缓存"引导（开飞行模式/重启目标 App） |
| R10 | 广告与业务同域，误拦导致 App 功能异常 | 中 | 中 | 白名单 + 误拦反馈 + 记录里可一键加白 |
| R11 | 高频 DNS 事件导致耗电/发热 | 中 | 中 | LRU 缓存、批量落库、归因缓存、可关闭归因 |
| R12 | 规则正则 ReDoS | 低 | 中 | 正则长度/编译耗时上限、禁用回溯构造、超时中断 |

## 3. 真机验证矩阵

| 维度 | 覆盖 |
|---|---|
| Android 版本 | 8.0 / 10 / 12 / 13 / 14 / 15（至少各 1 台或模拟器 + 真机） |
| ROM | 原生/AOSP、MIUI、ColorOS、HarmonyOS（Android 兼容层）、三星 One UI |
| 网络 | Wi-Fi、蜂窝、双卡切换、飞行模式、IPv6-only、私人 DNS 开/关 |
| 场景 | 冷启动开屏、热启动插屏、视频前贴、信息流横幅、WebView 广告、游戏自绘广告（预期失败） |
| 干扰 | 与代理 App 并存、分屏、折叠屏、深色模式、大字体、无障碍 TalkBack 同时开启 |

### 3.1 常用 adb 验证命令（Windows PowerShell）

```powershell
adb devices
adb install -r app-debug.apk

# 无障碍是否真的启用
adb shell settings get secure enabled_accessibility_services

# VPN 是否存在、属于哪个包
adb shell dumpsys connectivity | Select-String -Pattern "VPN|Vpn"

# 本进程 CPU / 内存
adb shell top -n 1 -b | Select-String -Pattern "adshield|PID"
adb shell dumpsys meminfo <package>

# 电量对比（记录前后两次）
adb shell dumpsys batterystats --charged <package> | Select-String -Pattern "Uid|Screen|mAh"

# 日志（建议 release 也保留关键错误）
adb logcat -s AdShield:V AndroidRuntime:E

# 模拟网络切换
adb shell svc wifi disable ; adb shell svc data enable
```

### 3.2 手工验证脚本（每轮回归必做，约 15 分钟）

1. 全新安装 → 走完 5 步引导 → 首页两盏状态灯均为开。
2. 打开 3 个含开屏广告的 App → 观察跳过与记录。
3. 打开白名单中的 App → 确认零点击。
4. 打开含"同意隐私政策"的 App → 确认不点、记录为 `SAFETY_BLOCKED`。
5. 关闭 Wi-Fi、开飞行模式、再恢复 → 拦截仍生效。
6. 强杀本 App → 系统应重启 VPN（或明确提示需手动开启）。
7. 导出 CSV → 检查行数与首页数字一致（允许 ±5% 的聚合误差）。
8. 连续刷视频 30 分钟 → CPU < 2%，无 ANR。

## 4. 上线/日用前检查清单

- [ ] 签名密钥已固定并离线备份
- [ ] `allowBackup=false`，无任何外传数据的代码路径（全仓搜索 `OkHttp` 调用点，仅允许规则订阅）
- [ ] release 关闭 debug 日志与诊断页入口（或加隐藏开关）
- [ ] 规则包许可与来源信息完整
- [ ] 帮助页写清能力边界（私人 DNS、DoH、WebView、游戏、系统代理、DNS 缓存）
- [ ] 一键关闭全部能力可用（应急）
- [ ] 权限清单与实际申请一致（用 `aapt dump permissions` 核对）
- [ ] 卸载残留检查（无外部文件写入）

## 5. 下一步需要你确认的事

1. 产品名与包名（默认 `com.example.adshield`，需替换）。
2. 是否接受"仅 DNS 层拦截"作为首版（不做 SNI/全流量）。
3. 无障碍规则的维护方式：全自建，还是允许用户手动添加社区订阅地址。
4. 是否需要上架应用商店（决定是否要拆"上架版"）。
5. 目标最低系统版本是否接受 **Android 8.0（minSdk 26）**。
6. 是否先做 M0+M1（能最快看到"真机拦截 + 次数统计"的效果）。
