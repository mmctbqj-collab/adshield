# 07 · 构建、安装与真机验证（M1 代码已生成）

## 0. 先说明一件事

本仓库的代码是在**没有 JDK / Android SDK / Gradle 缓存**的机器上生成的，因此**未经过实际编译**。
已完成的是逐文件静态自检（类型、引用、Room 注解、Manifest 与类名、权限与 API 级别）。第一次在 Android Studio 里同步时，若出现少量版本/API 报错，按 §7 的排查表处理即可，不会影响整体结构。

为降低不可验证条件下的构建风险，M1 做了两个取舍（与 `01-总体设计.md` 的多模块规划不同）：

| 规划 | M1 实际 | 原因 |
|---|---|---|
| 7 个 Gradle 模块 | **单模块 `:app` + 包分层** | 多模块 + KSP 跨模块注解处理出错面大，M1 优先跑通 |
| Hilt 依赖注入 | **手写 `AppContainer`** | 避免 Hilt/KSP/kapt 版本矩阵 |
| Room + DataStore | **Room + SharedPreferences** | DataStore 异步初始化在首屏会引入额外复杂度 |

M2 增加无障碍引擎时再按文档拆分模块，届时迁移成本很低（包边界已按模块划分）。

## 3. 构建步骤

### 3.1 用 Android Studio（推荐）

1. `File → Open`，选择本目录（含 `settings.gradle.kts` 的那一层）。
2. 首次会提示配置 Gradle：
   - 若提示 "Gradle wrapper 未找到"，选择 **Use local Gradle distribution**（AS 自带），或先执行 §3.2 生成 wrapper。
   - 不要选 "Use Gradle from gradle-wrapper.properties" 后直接点 OK —— 缺少 `gradle-wrapper.jar` 时会失败。
3. 等待 Sync。若提示缺少 SDK Platform 35，点 "Install missing platform"。
4. `Build → Build Bundle(s)/APK(s) → Build APK(s)`。

### 3.2 命令行（需要本机已装 Gradle 8.9+ 与 JDK 17）

```powershell
# 首次生成 wrapper（只需一次）
gradle wrapper --gradle-version 8.9

# 构建 debug
.\gradlew.bat :app:assembleDebug

# 产物
# app\build\outputs\apk\debug\app-debug.apk
```

### 3.3 安装

```powershell
adb devices
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

如果设备已登录厂商账号且提示"应用未安装/签名冲突"，先卸载旧版本：`adb uninstall com.adshield.app`。

### 3.4 没有 Android Studio：用 GitHub Actions 出包（最快上手机）

仓库已内置 `.github/workflows/android-debug.yml`（JDK 17 + Gradle 8.9 + SDK 35）：

1. 在 GitHub 新建一个仓库（私有也可以），把本目录所有文件推上去；
2. push 到 `main` / `master`，或到 Actions 页面手动 `Run workflow`；
3. 构建完成后进入该次 run → **Artifacts** → 下载 `adshield-debug-apk`；
4. 解压得到 `app-debug.apk`，直接传到手机安装（需允许"安装未知来源应用"），或 `adb install -r app-debug.apk`。

说明：
- debug APK 使用 Android 默认 debug 签名，**仅用于自测，不要对外分发**；
- 首次构建约 3–6 分钟（含依赖下载），之后有缓存会快很多；
- 若 CI 报错，把 run 日志中第一条 error 贴出来即可定位（常见是 SDK 版本或 Gradle 版本）。

### 3.5 本机（沙箱）为什么不能直接出包

本机没有 JDK / Android SDK，且出网被限制（`dl.google.com`、`repo1.maven.org` 均被拦截），
无法下载 SDK 与 Gradle 依赖，因此**只能在有网络的开发机或 CI 上构建**。

## 4. 首次使用流程

1. 打开 AdShield → 首页顶部显示"请求拦截未开启"。
2. 打开右上/卡片里的开关 → 系统弹出 **"连接请求"** 对话框（VpnService 授权）→ 允许。
   - 该对话框只出现一次；用户若点"取消"，`MainActivity` 会提示"未授予 VPN 权限"。
3. 通知栏出现常驻通知"广告域名拦截运行中"（Android 13+ 若未授予通知权限则只有 VPN 钥匙图标，功能不受影响）。
4. 首页大数字开始增长即表示 DNS 已被接管。

**重要前置检查**：设置 → 网络 → **私人 DNS** 若为"指定提供商"，本地过滤会失效，需要改为"自动"或"关闭"（M2 会在 App 内做检测提示）。

## 5. 验证拦截是否真的生效（4 步）

| 步骤 | 操作 | 期望结果 |
|---|---|---|
| 1 | 浏览器访问 `https://ad.qq.com` 或 `https://googleads.g.doubleclick.net` | 无法打开（DNS 解析失败 / 0.0.0.0），首页计数 +1 |
| 2 | 浏览器访问 `https://www.baidu.com` | 正常打开（说明没有误伤） |
| 3 | 打开一个带开屏广告的 App | 广告请求被拦，首页"拦截最多的域名/App"出现记录 |
| 4 | 关闭 Wi-Fi 切到 4G，重复步骤 1 | 仍然拦截失败（说明动态路由在工作；M1 已内置启动时读取当前网络 DNS） |

命令行旁证：

```powershell
# 是否真的建立 VPN（能看到 com.adshield.app）
adb shell dumpsys connectivity | Select-String -Pattern "VPN|Vpn"

# 域名解析结果：命中规则时应返回 0.0.0.0 或直接失败
adb shell ping -c 1 ad.qq.com
```

> 注意：**已缓存的 DNS 记录不会立即失效**。如果某个 App 在你开启拦截前刚解析过广告域名，可能需要强制停止该 App 或切换飞行模式再试。

## 6. 当前 M1 已知限制（预期内，不是 bug）

| 现象 | 原因 | 后续 |
|---|---|---|
| 部分 App 只显示"未归因" | ROM 的 `getConnectionOwnerUid` 返回 -1，或 Android 9 以下 | M1.1 记录归因成功率并在 UI 说明 |
| 私人 DNS 开启后完全失效 | DoT 绕过本地 DNS | M2 检测并弹引导 |
| 浏览器里的广告仍会出现 | 浏览器内置 DoH | 可把 `dns.google`、`cloudflare-dns.com` 加入自定义域名（会连带影响该浏览器的 DoH） |
| ping 8.8.8.8 失败 | 该 IP 被路由进 TUN，而 M1 只处理 UDP/53 | 预期行为，不影响正常上网 |
| 某些 App 首屏白屏/加载慢 | 主域名同域下发了广告接口，被后缀规则误伤 | 用"自定义域名"排查，或在设置中移除；M2 增加误拦反馈 |
| 开屏广告仍会弹出 | M1 不含无障碍引擎 | M2 |
| 打开本 App 通知看不到次数 | 未授予通知权限（Android 13+） | M3 加授权引导 |

## 7. 构建与运行排障表

| 报错/现象 | 处理 |
|---|---|
| `Gradle wrapper not found` / `gradlew` 不存在 | 用 AS 的 local Gradle，或执行 `gradle wrapper --gradle-version 8.9` |
| `Failed to find Platform SDK with path: platforms;android-35` | SDK Manager 安装 Android 15 (API 35) |
| `Unsupported class file major version 65` 之类 | Gradle/JDK 版本不匹配；确认 JDK 17 + Gradle 8.9 |
| `ksp` 版本与 Kotlin 不匹配 | 确认 `kotlin=2.0.21` 与 `ksp=2.0.21-1.0.28` 同时生效（都在 `libs.versions.toml`） |
| Room 报 `Schema export directory is not provided` | 确认 `ksp { arg("room.schemaLocation", "$projectDir/schemas") }` 与 `app/schemas` 目录存在 |
| `Unresolved reference: HorizontalDivider` | Compose Material3 版本过低；确认使用 BOM `2024.10.01` |
| 开启开关后没有 VPN 对话框 | 设备已有其它 VPN/代理在运行；先关闭其它 VPN；或检查是否被 MDM 策略禁止 |
| 开启后立即自动关闭并提示"已自动关闭过滤" | DNS 读循环异常退出，日志看 `adb logcat -s AdShieldDns:V`；常见原因是 TUN 被系统回收 |
| 首页数字一直是 0 | 1) 私人 DNS 未关；2) 目标 App 有 DNS 缓存；3) 规则未覆盖该域名（用"自定义域名"加一个已知广告域名验证） |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 之前装过不同签名的版本，先 `adb uninstall com.adshield.app` |

## 8. 内置规则库说明（M1 已扩充）

| 规则集 | 内容 | 默认 | 开关位置 |
|---|---|---|---|
| `BuiltinRules.ADS` | ~150 条广告 SDK / 广告平台域名：Google/AdMob、Meta、穿山甲/Pangle、优量汇、阿里妈妈/友盟、百度联盟、小米/OPPO/vivo/华为/荣耀/三星、Mintegral、Unity、AppLovin、Vungle/Liftoff、ironSource、InMobi、Chartboost、Tapjoy、AdColony、Amazon、Criteo、Smaato、PubMatic、Rubicon、OpenX、Taboola/Outbrain、Appnext、Start.io、Fyber 等 | **启用** | 无法关闭（单条域名可加白，见下） |
| `BuiltinRules.DOH` | `dns.google`、`cloudflare-dns.com`、`doh.pub`、`doh.alidns.com`、`dns.adguard-dns.com`、`dns.quad9.net`、`dns.nextdns.io` 等 | **关闭** | 首页「阻断加密 DNS（DoH）」 |
| `BuiltinRules.TRACKING_REFERENCE` | Adjust/AppsFlyer/Kochava/Singular/MIUI 统计 | 不启用 | 仅作为参考文本，需手动添加 |
| 用户自定义 | 任意域名（后缀匹配，覆盖全部子域） | — | 首页「自定义屏蔽域名」 |

**刻意不收录**会明显误伤的通用域名：`googleapis.com`、`gstatic.com`、`cloudfront.net`、`graph.facebook.com`、`connect.facebook.net`、`branch.io`、`appsflyer.com`。拦这些会导致 App 登录、推送、深度链接、分享功能异常，而收益极低。

**命中来源可追溯**：`DomainMatcher` 返回 `block:builtin` / `block:custom` / `block:doh`，已写入 `block_event.rule_id`，后续记录详情页可直接显示"被哪组规则拦下"。

**误拦处理**：首页「白名单（放行）」已提供，输入域名即时生效（规则快照热更新，无需重启 VPN），白名单优先于内置库、DoH 库与自定义黑名单。

## 9. 国产 ROM（MIUI / ColorOS / HarmonyOS）保活要点

国产 ROM 对后台服务与 VPN 的限制比原生 Android 严格，M1 建议按下列清单逐项确认：

### 9.1 通用（必做）

1. **电池优化白名单**：设置 → 应用 → AdShield → 电池 → 设为「无限制 / 不优化」。
2. **允许自启动 / 后台运行**：安全中心或应用管理中的"自启动""后台活动"开关。
3. **锁定后台**：任务列表里给 AdShield 加锁，避免一键清理时被清掉。
4. **通知权限**：Android 13+ 授予通知权限，否则前台服务通知不显示（功能仍工作，但用户容易误以为没开启）。

### 9.2 分厂商

| ROM | 关键路径 |
|---|---|
| MIUI / HyperOS | 设置 → 应用设置 → 应用管理 → AdShield → 省电策略「无限制」；安全中心 → 授权管理 → 自启动；关闭"锁屏后清理内存" |
| ColorOS / realme UI | 设置 → 电池 → 应用耗电管理 → AdShield → 允许后台运行 + 允许自启动；关闭"智能省电"对它的限制 |
| HarmonyOS | 设置 → 应用 → 应用启动管理 → AdShield → 关闭"自动管理"，手动开启「自启动 / 关联启动 / 后台活动」 |
| vivo OriginOS | i管家 → 应用管理 → 权限管理 → 自启动；后台高耗电允许 |

### 9.3 国产 ROM 的两个已知差异

1. **`getConnectionOwnerUid` 可能普遍返回 -1**：此时全部拦截会计入"未归因"，首页会显示"其中 N 次未能归因到具体 App"。这是系统限制，不是统计错误；M1.1 会加归因成功率诊断，避免用户误解。
2. **厂商"网络助手 / 流量节省"可能抢占 VPN**：若开启后立即被关闭，先关掉厂商的加速/省流开关，再重试；同时确认没有 Clash/游戏加速器在运行。

## 11. M2（已实现）：界面跳过的开启与验证

### 11.1 开启

1. 打开 AdShield，首页状态卡第二行显示「界面跳过未开启」。
2. 点 **去开启** → 系统无障碍设置页 → 找到 **AdShield 界面跳过** → 打开。
3. 弹窗会提示"该服务可以查看和控制屏幕内容"——这是自动点击的必要权限，只在本机使用。
4. 返回 App，状态应变成「界面跳过已开启」（MainActivity 在 onResume 重新读系统状态）。

### 11.2 验证（以 B 站为例）

| 步骤 | 操作 | 期望 |
|---|---|---|
| 1 | 强制停止 B 站（设置 → 应用 → 哔哩哔哩 → 强行停止），再冷启动 | 开屏广告出现后 1–2 秒内被自动点"跳过" |
| 2 | 回 AdShield 首页 | 「自动跳过」+1，「最近跳过」出现 `哔哩哔哩 · 已跳过` |
| 3 | 打开音乐类 App 听歌（不点跳过） | 不应误点"下一曲" |
| 4 | 打开带隐私弹窗的 App | 不应自动点"同意/允许"，记录里可能显示「安全阀拦下」 |

### 11.3 现在的限制（M2 MVP）

- **只处理前台 8 秒内**：开屏广告没问题；App 用久了才弹出的插屏广告不会被处理（防止误触）。
- **点击后不做"窗口消失"校验**：`SKIPPED` 表示"点击动作已成功下发"，不代表广告一定关掉了。M2.1 会加校验，把"点了没反应"的记为 `FAILED`。
- **规则是内置的 4 条**（B 站定向 + 通用文本/描述/viewId），没有订阅、没有自定义规则 UI。
- **WebView / 游戏引擎自绘广告**取不到节点，点不了（技术边界）。
- **同一 App 10 秒最多 3 次**、同一节点 30 秒只处理一次，避免连点。

### 11.4 误触了怎么办

1. 先关掉无障碍服务（设置 → 无障碍 → AdShield 界面跳过 → 关闭），立即停止一切自动点击。
2. 到 AdShield「最近跳过」看是哪条规则、哪个 App，把 `pkg` 与文本告诉我。
3. 我在 `SkipRules` 里收紧该规则（加包名限定、改精确文案、或直接移除）。

### 11.5 为什么 B 站只能靠这一步

B 站开屏/信息流广告与业务共用 `app.bilibili.com`，且自带 HTTPDNS 直连 IP，DNS 层既看不到也拦不了：
- 拦域名 → B 站整体不可用；
- 不拦 → 广告照常。
唯一可行是界面层点掉"跳过"，见 §11.2。
