# 05 · 权限、隐私与合规

> 本文不是法律意见。涉及分发（尤其上架应用商店）时，请以最新官方政策与实际法律意见为准。

---

## 1. 权限清单

### 1.1 普通权限（安装即授予）

| 权限 | 用途 | 必需 |
|---|---|---|
| `INTERNET` | 规则订阅下载、上游 DNS 转发 | 是 |
| `ACCESS_NETWORK_STATE` | 读取当前网络的 DNS 服务器、监听网络切换 | 是 |
| `FOREGROUND_SERVICE` | VPN 常驻前台服务 | 是 |
| `FOREGROUND_SERVICE_SPECIAL_USE`（API 34+） | 上述服务的类型声明 | 是 |
| `POST_NOTIFICATIONS`（API 33+） | 常驻状态通知与拦截提示 | 是（可降级为无通知运行） |
| `RECEIVE_BOOT_COMPLETED` | 开机后恢复无障碍开关状态与提示 | 可选 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 引导用户避免 VPN 被省电策略杀掉 | 可选 |

### 1.2 需要用户显式授权的系统组件

| 组件 | 授权方式 | 说明 |
|---|---|---|
| `VpnService` | `VpnService.prepare()` 系统弹窗 | 每次被撤销后需重新授权；`onRevoke()` 必须优雅退出 |
| `AccessibilityService` | 设置 → 无障碍 → 手动开启 | **无法用 Intent 直接开启**，只能跳转到设置页，且各厂商路径不同 |
| 包可见性 | `<queries>` 声明，或 `QUERY_ALL_PACKAGES` | 见 1.3 |
| 电池优化白名单 | `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 或引导手动 | 厂商 ROM 差异大 |

### 1.3 包可见性（Android 11+）

统计页要显示"是哪个 App"，必须能列出应用。两种做法：

1. **推荐（旁加载/开源分发）**：`<uses-permission android:name="android.permission.QUERY_ALL_PACKAGES"/>` —— 简单可靠。
2. **上架商店**：Google Play 对 `QUERY_ALL_PACKAGES` 有严格申报要求（需证明核心功能必需）。可退化为 `<queries>` 列举常见广告主 App + 通过 `getConnectionOwnerUid` 得到的包名做**按需查询**（`getApplicationInfo(pkg)` 对未知包也可能被过滤）。这条路可行性需在真机上逐版本验证，属于**上架专用分支**。

### 1.4 明确不需要的权限（也是安全卖点）

| 不需要 | 原因 |
|---|---|
| root / `su` | 全程免 root |
| `SYSTEM_ALERT_WINDOW`（悬浮窗） | 无需悬浮控件，避免遮挡与隐私争议 |
| `READ_LOGS`、`PACKAGE_USAGE_STATS` | 不读取使用记录；统计完全来自自己的两个引擎 |
| 存储读写权限 | 导出用 SAF（`ACTION_CREATE_DOCUMENT`），不申请存储权限 |
| 位置/通讯录/短信/相机/麦克风 | 与本功能无关，一个都不申请 |
| 账户体系 | 无登录、无云端 |

> **权限最小化即产品主张**：安装页展示"本 App 只申请 2 个核心系统能力（VPN、无障碍）+ 4 个普通权限"。

## 2. 首次使用引导（Onboarding，5 步）

```
Step 1  说明能力与边界（含"不会/不能做什么"）→ 用户确认
Step 2  开启请求拦截：prepare() 授权 → 检测其它 VPN → 检测私人 DNS → 给出处理指引
Step 3  开启界面跳过：跳转无障碍设置 → 返回后校验 → 首次演示（在演示页跑一个真实的匹配流程）
Step 4  通知权限（可选）+ 电池优化白名单（可选）
Step 5  选择默认隐私级别与保留天数 → 完成
```

每一步都必须能"稍后再说"，且首页状态灯持续提示未开启项。**不做强制引导，不做欺骗性按钮**（例如把"同意"做成唯一可点项）。

## 3. 分发渠道与商店政策风险

| 渠道 | 可行性 | 关键约束 |
|---|---|---|
| 自用侧载（adb / 直接安装 APK） | **最推荐，风险最低** | 无审核；需自行管理签名与更新 |
| 开源 + GitHub Releases | 推荐 | 需保留规则来源许可与署名；提供校验和 |
| F-Droid | 可行 | 要求完全开源、可复现构建、无专有依赖、无追踪 |
| Google Play | **风险高** | 见下 |
| 国内应用商店 | 风险高 | 广告拦截类通常不予上架；且 VPN 类需资质 |

### 3.1 Google Play 的两条高危政策

1. **VpnService 政策**：使用 `VpnService` 必须声明为核心功能，不得用于绕过运营商限制、不得收集转发内容。广告拦截属于"设备本地过滤"，可解释，但审核会重点看隐私政策与数据流向（本项目无外传，有利）。
2. **无障碍（AccessibilityService）政策**：只允许用于（a）辅助残障用户，或（b）**应用自身核心功能**且已取得用户明确同意并披露。自动点击他人 App 的界面，历史上被大量下架。`isAccessibilityTool="false"` 会进入更严格的人工审核。

**结论**：本项目定位为**个人使用 / 开源工具**，优先侧载分发；若要上架，建议把"无障碍自动点击"做成可选插件或独立 APK，主包只保留 DNS 拦截（上架成功率显著提高）。

## 4. 法律与道德边界

### 4.1 会做（风险可控）

- 在**自己拥有的设备**上，对**自己安装**的应用产生的网络请求做本地过滤。
- 自动点击**自己设备上**界面的"跳过/关闭"按钮。
- 记录并展示本机统计。

### 4.2 不会做（红线）

| 红线 | 原因 |
|---|---|
| 修改、反编译、重打包他人 App | 侵犯著作权，可能触犯《著作权法》与《计算机软件保护条例》 |
| 破解会员 / 绕过付费墙 | 同上，且违反服务条款 |
| 拦截他人设备 / 分发"去广告版"App | 可能构成不正当竞争（《反不正当竞争法》），并侵害广告主与平台利益 |
| 把拦截能力做成 SDK 供第三方嵌入 | 商业化拦截他人广告，法律与舆论风险极高 |
| MITM 解密 HTTPS 内容 | 破坏传输安全，且与"过滤域名"的目标无关 |

### 4.3 需要向用户明确告知的事实

- 部分 App 以广告为对价提供服务，屏蔽后可能：功能受限、强制登录、弹"检测到广告拦截"提示、甚至拒绝服务。这属于用户选择的后果，App 内应提示而非隐瞒。
- 用户应自行确认其与各 App 的服务协议是否允许拦截。**本项目不鼓励也不协助规避付费**。
- 不提供任何"破解"功能，不内置任何他人 App 的修改版。

## 5. 规则与数据来源的许可

| 来源 | 内容 | 处理方式 |
|---|---|---|
| AdAway / DNS66 的默认 hosts 源 | 域名黑名单 | 分发前逐个核实许可（多为 GPL/CC/MIT 混合），**保留 LICENSE 与来源链接**；更稳妥：不在 APK 内置，改为用户添加订阅地址 |
| AdGuard DNS filter / EasyList 等 | 过滤规则 | 多为 GPL-3.0 或 CC BY-SA，衍生物需同许可；若集成需评估传染性 |
| GKD 及同类社区规则 | 界面规则 | GPL-3.0；**只借鉴产品思路，不复制规则文件与代码** |
| 自建规则 | 本项目原创 | 建议以 CC BY-SA 4.0 发布，鼓励回馈 |

**操作规范**：
1. 规则包元数据里强制包含 `sourceUrl`、`license`、`author`，UI 上可查看。
2. 内置规则只包含本项目原创的通用规则。
3. 订阅下载失败不影响已启用的旧规则。

## 6. 隐私与安全实现要求

| 要求 | 落地 |
|---|---|
| 无服务器 | 无后端、无账号；唯一网络出口是规则订阅 |
| 不采集标识 | 订阅请求不带 Android ID / IMEI / 广告 ID |
| 本地加密（可选） | 数据库可加 `SQLCipher`（代价：体积与性能），默认不启用 |
| 备份 | `allowBackup="false"`，防止数据库随云备份外泄 |
| 导出脱敏 | 导出前可选"域名打码/包名打码" |
| 日志 | release 关闭详细日志；debug 日志保留在内存环形缓冲，用户手动导出 |
| 签名 | 固定签名密钥（放本地，不入库）；提供 APK 校验和 |
| 更新 | 自建更新检查（可选）时只校验版本号与签名，不下载自动安装 |
| 恶意规则防护 | 规则订阅启用签名校验（可选 Ed25519），至少校验 HTTPS + JSON schema，防注入超长正则（ReDoS 限制见 03 文档） |

2. 明确"不修改任何第三方应用"。
3. 明确"规则与域名列表的来源、许可与免责"。
4. 明确"广告拦截可能导致部分应用功能异常，用户自担风险"。
