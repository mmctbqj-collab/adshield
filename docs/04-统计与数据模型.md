# 04 · 记录与统计：数据模型 + 报表设计

## 1. 统计口径（先说清楚，再决定怎么算）

用户看到"拦截了 128 次广告"时的期待是"省了 128 次广告时间"，但技术上是"128 次域名请求"。为避免夸大，App 内统一使用**四级口径**，界面上明确区分：

| 口径 | 定义 | 准确性 |
|---|---|---|
| **拦截请求数** | DNS 层被阻断的查询次数（按域名+分钟聚合去重） | 高（技术事实） |
| **广告事件数** | 30 秒时间窗内、同一 App 的多次拦截聚合为 1 次"广告事件" | 中（启发式） |
| **弹窗出现数** | 无障碍层判定为广告弹窗的界面出现次数 | 中高（规则驱动） |
| **自动跳过数** | 点击后界面确实消失的次数 | 高（有校验） |

首页主指标用**「拦截请求」+「自动跳过」**两个确定量，副指标才用"约省 4 分 12 秒"并标注"估算"。

## 2. 数据模型（Room）

### 2.1 表结构

```sql
-- 已安装应用信息（列表与图标缓存，避免每次查 PackageManager）
CREATE TABLE app_info (
  pkg            TEXT PRIMARY KEY,
  label          TEXT NOT NULL,
  is_system      INTEGER NOT NULL DEFAULT 0,
  first_seen_ts  INTEGER NOT NULL,
  last_seen_ts   INTEGER NOT NULL
);

-- 域名拦截原始事件（节流聚合后写入）
CREATE TABLE block_event (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  ts         INTEGER NOT NULL,        -- 事件时间（毫秒）
  day        TEXT    NOT NULL,        -- yyyy-MM-dd（本地时区，用于分区与聚合）
  domain     TEXT    NOT NULL,        -- 如 ad.qq.com
  pkg        TEXT,                    -- 可归因时为包名，否则 NULL
  uid        INTEGER NOT NULL DEFAULT -1,
  rule_id    TEXT,                    -- 命中的规则 id（订阅/自定义来源）
  hit_count  INTEGER NOT NULL DEFAULT 1,   -- 同一 (day,domain,pkg) 桶内计数
  network    INTEGER NOT NULL DEFAULT 0    -- 0 未知 1 wifi 2 cellular
);
CREATE INDEX idx_block_day_pkg  ON block_event(day, pkg);
CREATE INDEX idx_block_domain   ON block_event(day, domain);

-- 弹窗事件（出现 / 跳过 / 被安全阀拦下）
CREATE TABLE popup_event (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  ts          INTEGER NOT NULL,
  day         TEXT    NOT NULL,
  pkg         TEXT    NOT NULL,
  activity    TEXT,
  rule_id     TEXT,
  node_text   TEXT,                  -- 命中的控件文本（脱敏截断 64 字）
  outcome     TEXT    NOT NULL,      -- DETECTED | SKIPPED | SAFETY_BLOCKED | FAILED
  method      TEXT,                  -- CLICK | ANCESTOR_CLICK | GESTURE | NONE
  latency_ms  INTEGER,               -- 从窗口出现到点击生效的耗时
  confidence  INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_popup_day_pkg ON popup_event(day, pkg);

-- 日聚合表（报表只查这里，不扫原始表）
CREATE TABLE daily_stat (
  day             TEXT NOT NULL,
  pkg             TEXT NOT NULL DEFAULT '',   -- '' 表示全局汇总行
  blocked_requests INTEGER NOT NULL DEFAULT 0,
  ad_events        INTEGER NOT NULL DEFAULT 0,
  popup_detected   INTEGER NOT NULL DEFAULT 0,
  popup_skipped    INTEGER NOT NULL DEFAULT 0,
  skipped_ms       INTEGER NOT NULL DEFAULT 0,
  unattributed     INTEGER NOT NULL DEFAULT 0, -- 未能归因的拦截数
  PRIMARY KEY (day, pkg)
);
CREATE INDEX idx_daily_pkg ON daily_stat(pkg, day);

-- 规则命中统计（用于规则质量评估与下架）
CREATE TABLE rule_hit (
  day      TEXT NOT NULL,
  rule_id  TEXT NOT NULL,
  hits     INTEGER NOT NULL DEFAULT 0,
  success  INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (day, rule_id)
);
```

### 2.2 写入策略

| 环节 | 策略 |
|---|---|
| 采集 | 引擎只写内存计数器：`Map<BucketKey, AtomicInteger>`，BucketKey = (day, domain, pkg) / (day, ruleId) |
| 落库 | 每 5 秒 flush 一次；进程 `onTrimMemory`/Service 停止时强制 flush |
| 事务 | 每次 flush 单事务批量 upsert，`block_event` 用「同 key 合并 + hit_count += n」避免行爆炸 |
| 聚合 | `daily_stat` 由 flush 时同步累加（写少读多），另设夜间 WorkManager 全量重算兜底（防丢） |
| 保留 | 默认 90 天；原始表按 `day < cutOff` 删除，`daily_stat` 永久保留（体积极小） |
| 容量 | 日均 300–800 桶 → 90 天约 3–7 万行，< 20MB；索引后查询 p95 < 60ms |

### 2.3 时间与时区

- `day` 用**本地时区**计算；用户改时区/时间穿越会导致桶错位，处理方式：聚合任务检测 `day` 跳变（前一天缺失）时插入空行，不做回填修正（简单、可解释）。
- 展示时间线按设备时区；导出附 `timezone` 字段。

## 3. 报表与查询

### 3.1 查询清单（`StatsRepository`）

| 查询 | SQL 要点 | 用途 |
|---|---|---|
| 今日总览 | `daily_stat WHERE day = ?` | 首页大数字 |
| 近 N 日趋势 | `WHERE pkg = '' AND day BETWEEN ? AND ? ORDER BY day` | 柱状图 |
| 按 App 排行 | `WHERE day >= ? AND pkg <> '' GROUP BY pkg ORDER BY sum(...) DESC LIMIT 10` | 排行卡 |
| 某 App 详情 | `WHERE pkg = ? AND day >= ?` | App 详情页 |
| 域名 Top | `SELECT domain, SUM(hit_count) FROM block_event WHERE day >= ? GROUP BY domain ORDER BY 2 DESC LIMIT 20` | 诊断"拦了谁" |
| 记录列表 | 分页 `ORDER BY ts DESC`，游标 = `(ts, id)` | 时间线（不用 OFFSET） |
| 规则质量 | `GROUP BY rule_id` 算 success/hits | 规则下架决策 |

### 3.2 指标计算规则

```kotlin
// "广告事件数"：同 pkg 相邻两次拦截间隔 <= 30s 视为同一事件
fun countAdEvents(timestamps: List<Long>): Int =
    timestamps.sorted().fold(0 to Long.MIN_VALUE) { (n, last), ts ->
        if (ts - last > 30_000) n + 1 to ts else n to last
    }.first

// "节省时间"：默认 5s/次跳跃（可在设置中改为 3/5/8s），仅展示为"约"
val savedMs = popupSkipped * perSkipMs + blockedRequests * 0L   // 拦截不计时间，只计跳过
```

**注意**：不要把"拦截请求数 × 5 秒"相加——那会把一次广告的 12 个请求算成 60 秒，明显夸大。

## 4. 界面设计（Compose）

### 4.1 首页（仪表盘）

```
┌───────────────────────────────────────────┐
│ AdShield                         [⚙]      │
├───────────────────────────────────────────┤
│  ● 请求拦截 已开启     ○ 界面跳过 已停用   │  ← 两枚状态灯，点击直接跳授权
├───────────────────────────────────────────┤
│      今日                                     │
│        128               14                  │
│    拦截请求            自动跳过               │
│    约省 1 分 10 秒（估算）                    │
├───────────────────────────────────────────┤
│  近 7 日                      ▁▃▅▂▇▄█       │
├───────────────────────────────────────────┤
│  拦截最多                    全部 >          │
│  ▣ 某视频 App    62 次    ▣ 某资讯 App  31 次│
│  ▣ 某购物 App    18 次    ▣ 未知来源    17 次│
└───────────────────────────────────────────┘
```

要点：
- "未知来源"必须是**可点击的普通条目**，点进去解释"设备不支持按 App 归因"或"部分系统流量无法归属"，不做隐藏。
- 开关开启前显示前置条件清单（VPN 授权 / 关闭私人DNS / 当前无其它 VPN）。

### 4.2 记录页

- 顶部 Tab：`全部 / 请求 / 弹窗`。
- 每条：App 图标（无归因时显示地球图标）、标题（域名 或 "开屏广告"）、副标题（规则名 / activity 简称）、右侧时间、状态徽标（已拦截 / 已跳过 / 已发现未跳过 / 被安全阀拦下）。
- 行点击 → 详情：原始字段 + "加入白名单"（域名或 App）+ "我点错了/误拦"反馈入口。
- 支持按 App 筛选、按日期跳转。

### 4.3 规则页

- 分区：已安装规则包（内置 / 订阅 / 自定义）、每个包显示版本、条数、开关、最后更新时间。
- 单条规则可搜索（按 App 名、规则名）、可单独停用。
- "测试规则"：对当前前台 App 立即跑一次匹配，显示命中的节点（debug 风格界面，帮助用户理解）。

### 4.4 设置页

| 项 | 默认 | 说明 |
|---|---|---|
| 引擎开关 | 请求拦截默认关，界面跳过默认关 | 首次必须用户主动开启 |
| 上游 DNS | 跟随系统 | 可选 1.1.1.1 / 阿里 / 腾讯 / 自定义 |
| 命中应答 | 0.0.0.0 | 可切 NXDOMAIN |
| 归因 | 开（API≥29） | 可关（省电） |
| 保留天数 | 90 | 30/90/180/永久 |
| 每次跳过计为 | 5 秒 | 用于估算 |
| 白名单 | 空 | App + 域名 两组 |
| 导出 | — | CSV / JSON，`ACTION_CREATE_DOCUMENT` 保存 |
| 清空数据 | — | 二次确认，删除原始表（保留日聚合可选） |

## 6. 隐私设计

- 所有数据仅存本机 `Room + DataStore`；**无服务器、无账号、无上报**。
- 唯一联网行为：规则订阅下载（可完全关闭）。请求只带 `If-None-Match`/版本号，不携带任何设备标识（必要时用随机 UA，不用 Android ID）。
- 域名记录本身可视为浏览行为侧信道：设置页提供"只保留域名哈希/只保留 Top 域名/不记录域名"三档隐私级别。
- 卸载即删除；提供"一键清空"。
- Android 系统备份：`android:allowBackup="false"`（防止数据库被云备份带走）。

## 7. 统计数据的可信度提示（写进 App 帮助页）

> - 请求拦截数 = 被丢弃的域名查询次数，按"域名+App+分钟"去重，不等于广告展示次数。
> - 部分流量无法确定来源 App，会归入"未知来源"，这是 Android 系统限制，不是统计错误。
> - 已知问题：开启拦截后的短时间内，App 可能因 DNS 缓存仍能加载旧广告（建议重启目标 App）。
> - 自动跳过依赖界面规则，规则未覆盖的 App 仍会显示广告，可反馈或自行添加规则。
