# AdShield · Android 广告域名拦截与计数（M1）

在**自己设备**上拦掉其它 App 的广告请求，并记录"拦了多少、是哪个 App"。免 root，数据不出本机。

- 平台：Android，minSdk 26 / targetSdk 35
- 技术路线：本地 VPN（TUN 只捕获 DNS 53）→ 域名规则匹配 → 空应答；配合 Room 统计
- 明确不做：反编译/重打包他人 App、破解会员、MITM 解密 HTTPS

## 代码结构（M1，单模块）

```
app/src/main/java/com/adshield/app/
├─ AdShieldApp.kt          Application + AppContainer（手写 DI，未用 Hilt）
├─ data/                   Room 库、SharedPreferences、内存聚合落库
├─ rules/                  域名后缀匹配、hosts 解析、内置规则
├─ ui/                     Compose 首页 + ViewModel + VPN 授权
└─ vpn/                    VpnService、TUN 参数、DNS 编解码、上游转发、uid 归因
```

> M1 刻意用「单模块 + 手写 DI」而不是设计稿的 7 模块 + Hilt：在无法本地编译验证的条件下，这是把"能跑起来"的确定性放到最高。包边界已按模块划分，M2 拆分成本很低。

## 三条关键设计结论

1. **只路由 DNS 目标**，不用 `0.0.0.0/0` 全路由。全路由会吃掉所有流量而本模块没有 TCP/IP 转发能力 → 整机断网。
2. **按 App 统计有硬上限**：`getConnectionOwnerUid`（Android 10+）是唯一免 root 路径，很多 ROM 返回 `-1`，此时如实计入"未归因"，不猜测。
3. **DNS 读循环必须熔断**：读循环意外退出时 TUN 仍在、DNS 会全部超时（表现为"断网"），所以退出时通知 Service 立即关闭 VPN 恢复上网。

## 已知边界（写进 App，也写进文档）

私人 DNS（DoT）、App 内置 DoH、广告与业务同域、已缓存的 DNS 记录、浏览器内广告 —— 这些场景 M1 拦不住，属技术边界而非缺陷。
